## 2026-09-05 05:55 cvrp: iters 5-8, spend $8.63, champion -0.0550, beating best-known: none

### What worked
- iter 8 (champion, -0.0679 → -0.0550): restructured the granular LS so all per-customer data (position, incident edges, Or-opt segments with gains/demands, prefix load) is computed once per `_improve` call and reused across the neighbour scan, plus O(1) position arrays reindexed per route. Mechanism: more ruin-and-recreate iterations per second; every gap on the board shrank, largest in absolute terms on X-n336/X-n480/X-n491 where the interpreter cost per LS call was highest. This is the third consecutive win from the same lever (iters 1, 2, 8 = the only champions ever): raw R&R throughput in pure Python.

### What didn't
- iter 5 (fleet minimisation phase, -0.0802): spent the early budget removing a route the SA would find anyway; the ~k route counts are already reached by the whole-route ruin, so it bought nothing and cost iterations.
- iter 6 (memetic elite pool + stall restarts, -0.0786) and iter 3-style intensification: extra machinery per stall, fewer R&R iterations; on 120s the pool never gets enough distinct optima to matter. Same failure class as iter 3 (SWAP*) and iter 4 (LS gating model): anything that adds Python work per iteration loses to the throughput it displaces.
- iter 7 (symmetric relocate/Or-opt, -0.0680 vs champion -0.0679): not a real rejection — a 1e-4 difference on a single-seed total is inside run-to-run noise. Duplicate in spirit of iter 1's move-set expansion; verdict is unknowable without seed replication.

### Lessons
- Only throughput changes have ever become champion (iters 1, 2, 8); every added neighbourhood, model or phase (3, 4, 5, 6) was rejected — profile the LS loop before adding anything to it.
- Single-seed totals separated by <0.005 are noise (iter 7 vs iter 2); a rejection at that margin wastes an iteration and hides a possible win.
- The gap is uniform (0.22%–0.76%, worst X-n411-k19 0.76%, X-n491-k59 0.69%), so it is search depth, not construction or numerics; no target is an outlier that a special-case fix would close.
- 0.2–0.7% at 120s in pure Python is already near the ceiling for an SA+SISR engine; beating a BKS needs either an order of magnitude more effective iterations or a different acceptance/diversification regime, not another move.
- The scoring gate is on the summed total, so a change that helps the 400+ instances but hurts the 280–330 ones by more is rejected; test per-target before submitting.
