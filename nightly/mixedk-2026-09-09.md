# Mixed-K SAT encoder — 2026-09-09

## What it is

`mixedk_sat.py`: direct rank search for 3×3 matrix multiplication with a
**per-triple sparsity budget**. Triple r may use at most `k_list[r]` nonzeros
in each of its U/V/W factor matrices. Same tensor-identity + binary
adder-tree encoding as `satenc2_adder.py` — the only change is that the
`CardEnc.atmost` bound varies per triple instead of being uniform.

New file; `satenc2_adder.py` / `lns_sat.py` untouched (imports only the
`half_adder` / `sum_equals_adder` helpers).

## Why

Laderman's rank-23 needs K=7, but only 6 of its 23 triples need it:

| K (per-triple max-nz) | 1 | 2 | 3 | 7 |
|---|---|---|---|---|
| # triples | 5 | 8 | 4 | 6 |

Uniform K=7 searches a space of 10^291.67 assignments; the mixed-K space
(Laderman-derived budgets) is 10^183.42 — a **10^108 reduction** — while still
containing every Laderman-class solution. Per-matrix assignment counts:
K=1→19, K=2→163, K=3→835, K=7→16867 (of 3^9=19683 total).

## Honest size comparison (R=23, n=3)

| Encoding | Clauses | Vars | Build |
|---|---|---|---|
| mixed-K (Laderman budgets) | 1,579,144 | 456,226 | 6.3s |
| uniform K=7 | 1,578,712 | 456,268 | 5.4s |

**Mixed-K does not shrink the CNF** (−0.1% clauses). The tensor-identity
gadgets (729 equations × R triples) and the adder trees dominate; the 69
cardinality constraints are ~0.1% of clauses, and pysat's seqcounter for
K=7/9 is already near-minimal (23 clauses vs 39 for K=3). The win is
entirely in **solver search-space pruning**: tight bounds (e.g. K=1 forces
8 of 9 entries to zero) propagate hard and collapse the search tree, where
uniform K=7 barely constrains anything.

## Verification (2026-09-09)

`mixedk_sat.py selftest` — **PASS** (15.4s):
1. Laderman's 23 triples loaded; each triple's actual max-nz fits its budget
   by construction (budgets *are* the measured max-nz values).
2. All entries pinned to Laderman's values via unit clauses → solver returns
   **SAT in 3.2s** (encoding admits the known-feasible point).
3. Exact verifier `check(fac, 3)` → `{'feasible': True, 'rank': 23}`.
4. Size comparison table above.

Timeout enforcement also verified: `mixedk_sat.py 8 "3,3,3,3,3,3,3,3" 1 0`
printed `TIMEOUT (1s, solve 1.0s)` and exited cleanly. (Implementation note:
pysat 1.9.dev15 `Cadical103` has no wall-clock limit — `solve_limited` is
conflict/decision budgets only, and SIGALRM can't interrupt the C solver —
so the solve runs in a forked child process that the parent `terminate()`s
on expiry. The timeout covers the solve phase; CNF build is untimed, ~6s.)

## How to run

```
~/workspace/discovery-loop/.venv/bin/python mixedk_sat.py <R> <k_csv> <timeout> <seed>
```

- `R`: number of triples.
- `k_csv`: comma-separated per-triple K (`"7,2,7,3,..."`, exactly R values);
  a single value broadcasts to all triples (uniform search). Omit for R=23
  to use the Laderman-derived budgets automatically.
- `timeout`: solve-phase seconds (`0` = no limit).
- `seed`: accepted for interface compatibility; the encoding is deterministic.

Examples:
```
# selftest: known-feasible check + size table
python mixedk_sat.py selftest

# R=23 with Laderman budgets, 30-min budget
python mixedk_sat.py 23 "" 1800 0

# R=22, Laderman-minus-triple-19 budgets (drop the 19th entry of the default list)
python mixedk_sat.py 22 "7,2,7,3,2,7,3,2,2,7,7,3,2,7,2,3,2,2,1,1,1,1" 5400 0
```
On SAT the decomposition is verified with the exact checker and saved as
`rank<R>-mixedk-<date>.json`.

## What a first real R=22 mixed-K search would cost

Measured: CNF builds in **5.3s** → **1,498,048 clauses / 432,793 vars**
(Laderman-minus-19 budgets).

Solve time is the unknown. Data points:
- Direct R=26 K=2 adder search: **timeout at 600s** (2.09M clauses) — no verdict.
- LNS remove-1 + 6-triple K=7 re-optimization: **UNSAT in ~630s** (246k clauses)
  — but that's 6 free triples, not 22.

A direct R=22 mixed-K search frees all 22 triples: strictly harder than LNS,
strictly easier than the R=26 K=2 attempt (smaller CNF, far smaller search
space per the 10^108 argument — though solver time doesn't scale linearly
with that). Honest estimate: **budget hours, expect a 90-minute timeout**;
run it as an overnight background job alongside LNS, not as a blocking
experiment. A SAT result is a world record (rank 22 < Laderman's 23, unbroken
since 1976) — verify with the exact checker before claiming anything. An
UNSAT at some budget is *not* a proof of rank ≥ 23 (it's one K-assignment),
but each exhausted K-assignment is a durable data point for the dead-ends
ledger — record the exact k_csv, budget, and verdict.

Suggested first shot: the R=22 command above (Laderman-minus-19 budgets,
5400s), then Laderman-minus-21 budgets, then wider K assignments if those
return UNSAT fast.
